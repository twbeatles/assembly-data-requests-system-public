# 요구자료 취합 포털 구현 현황과 정식 운영 과제

취합팀은 중앙 포털 DB에서 요구를 접수하고 부서를 배정할 수 있다. 부서는 배정된 건에 한글 원본을 제출하며, 취합팀은 보완·승인·최종 확정을 처리한다. 회사 포털에는 접수·상태 조회 API가 제공된다. 정식 전환에는 회사 계정 연동과 운영 환경 검증, 첨부 검사, 복구 훈련이 필요하다.

## 구현 완료

| 영역 | 동작 |
| --- | --- |
| 접수·배정 | 취합팀 등록 또는 외부 API 접수 후 부서별로 배정하고 내부 마감일을 정한다. |
| 부서 검색과 조회 | 중앙 DB에 대해 계정의 부서·취합팀 권한을 조회할 때마다 검사한다. 공동 배정 건은 공통 요구와 양식을 공유하고, 부서 답변과 첨부는 담당 부서 범위에서 검색·열람한다. 검색 대상은 요구·답변 본문, 첨부 파일명, 업무 공지다. |
| 한글 문서와 제출 | HWP 5.x·HWPX 양식 배포, 파일만으로 제출, 보완과 재제출, 원본 첨부와 제출 이력을 지원한다. 최종 한글 원본은 확정 판별로 남으며, 단독 파일 또는 승인 첨부가 포함된 ZIP으로 내려받을 수 있다. |
| 취합과 공지 | 취합팀이 제출본을 승인하고 책임자가 최종본을 확정한다. 배정·제출·승인·보완·확정 상태를 공지함에 연결하고, 취합팀은 지정 부서에 업무 공지를 보낼 수 있다. 읽음과 이전 링크 접근은 현재 계정 권한을 확인한다. |
| 회사 포털 연동 | 서버용 키로 접수 및 자체 접수 건의 상태를 조회한다. 같은 외부 ID를 같은 내용으로 재시도하면 중복 등록을 방지한다. 키는 만료·교체·회수가 가능하다. |
| 운영과 복구 | 권한 확인, 감사 이력 내보내기, 일관된 SQLite 백업, 무결성 확인, 복구본의 세션·연동 키 폐기가 제공된다. 기존 포털 DB는 사용 시작 시 스키마 4로 이관된다. |

대외 제출 상태와 제출일은 포털에 기록한다. 기존 02번 대장과 마스터 엑셀을 갱신한 후 포털에서 대장 반영을 수동 확인한다. 부서 답변 입력란은 검색할 수 있으며, HWP·HWPX 파일 속 본문 검색에는 문서 추출 처리가 필요하다.

## 다음 작업

| 우선순위 | 작업 | 완료 기준 |
| --- | --- | --- |
| 정식 전환 전 | 회사 SSO·MFA 및 인사 연동 | 실제 IdP로 로그인하고 승인된 사용자 매핑을 검증한다. 전보·퇴직·정지 시 기존 세션과 부서·취합 권한이 합의된 시간 안에 회수된다. |
| 정식 전환 전 | HTTPS 프록시·네트워크와 운영 계정 | 직원용 포털과 제휴 API의 접속 경계를 실제 환경에서 검증한다. 인증 헤더와 민감한 본문을 제외한 감사 기록을 중앙 수집하고, 작업별 운영 담당자를 지정한다. |
| 정식 전환 전 | 업로드 검사·서식 검수 | 실제 HWP·HWPX 양식의 표·그림·쪽 설정을 기관 한글 환경에서 열어 확인한다. 악성코드 검사·격리·재제출 절차와 보관 기간을 정한다. |
| 정식 전환 전 | 인수·부하·복구 시험 | 취합팀과 제출 부서가 접수부터 대외 제출까지 시험한다. 예상 동시 사용자와 대용량 첨부를 측정하고, 별도 환경에 복구해 권한·키 재발급·파일 해시를 확인한다. |
| 운영 개선 | 02번 대장·엑셀 자동 연계 | 실제 대외 제출이 확인된 경우에만 대장을 갱신한다. 재시도 중복, 수기 변경 충돌, 엑셀 잠금과 최종 반영 여부를 검증한다. |
| 운영 개선 | 전자결재·메일·메신저 통지 | 회사가 승인한 채널과 재전송·감사 기준을 적용한다. 통지 수신자가 현재 권한으로 해당 포털 링크를 열 수 있는지 확인한다. |
| 확장 검토 | 한글 서식 자동 작성과 첨부 본문 검색 | 대표 기관 서식의 실제 열기·편집을 검증한다. 추출 워커를 분리하고, 기존 문서 버전과 검색 권한 경계를 함께 확인한다. |

## 문서와 배포본

- 초기 실행, 부서 권한 설정과 공지 사용은 [취합 포털 시범 운영 가이드](COLLECTION_PORTAL.md)를 따른다.
- 회사 연결, 키 발급·회수, 백업·복구와 GitHub 권한 사례는 [외부 연동 및 정식 운영 설계](COLLECTION_PORTAL_OPERATIONS.md)에 있다. 호출 형식은 [OpenAPI 계약](collection-portal-openapi.yaml)에서 확인한다.
- 범용 패키지는 빈 검색 DB와 대시보드, 실행 스크립트, 포털 운영 문서를 포함한다. 포털 DB는 배포본의 `data_requests.db`와 별도의 경로로 지정한다. 업무 자료와 사용자 계정은 조직 운영 환경에서 등록한다.
- 빌드에 사용하는 Python과 의존성은 `requirements.txt`를 기준으로 준비한다. 데스크톱 실행 파일은 Windows에서 PyInstaller의 `--onefile --windowed --paths scripts` 옵션으로 `scripts/launcher_gui.py`를 묶어 `dist/자료요구_통합검색.exe`에 둔다. 범용 패키지 생성기는 이 실행 파일을 찾으면 함께 묶는다.

저장소 루트에서 빌드 출력 경로를 지정해 범용 패키지를 만들 수 있다.

```powershell
python -m pip install -r requirements.txt
python -c "from pathlib import Path; from scripts.build_universal_package import build_universal_package; build_universal_package(Path('dist/universal'))"
```

배포본 검증에는 데이터가 비어 있는지, 포털 CLI가 실행되는지, 부서 계정이 자기 배정만 검색하는지, HWP·HWPX 원본과 공지 대상 범위가 보존되는지를 포함한다. 정식 운영 환경 검증 항목은 위 표에 따른다.
